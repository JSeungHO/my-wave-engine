# Phase 4 검증 가이드 — “물이 막히는지” 어떻게 확인하나

> **대상:** 차수벽·건물 마스크 데모를 보고 **막힘 여부가 불분명**할 때  
> **관련:** [FLOOD.md](../frontend/docs/FLOOD.md) · [ROADMAP.md § Phase 4](./ROADMAP.md#phase-4--장애물--차수벽-poc)

---

## 1. 한 줄 요약

**지금 구현은 “물이 갈라지거나 흐름이 바뀌는” 시뮬레이션이 아닙니다.**  
**장애물 AABB 안의 수면 픽셀만 `discard`로 지웁니다.**  
그래서 멀리서 보면 **막히는지 거의 구분이 안 됩니다.**

---

## 2. 현재 Phase 4가 하는 일 / 하지 않는 일

| ✅ 하는 일 | ❌ 하지 않는 일 |
|-----------|----------------|
| `obstacles.json` 차수벽·건물 박스 배치 | 2D 홍수 흐름 (물이 옆으로 갈라짐) |
| Cesium에 노란 차수벽·건물 박스 표시 | Navier–Stokes / 유체 역학 |
| GPU fragment: 장애물 **내부** 수면 픽셀 제거 (`discard`) | 차수벽 **뒤 전체**를 육지처럼 dry |
| 장애물 경계 ~9m **edge foam** (연한 거품) | 파도 **높이**가 벽에서 물리적으로 반사 |
| CPU `ObstacleField.isDry()` | 선박·카메라가 막힘을 체감하는 연출 |

**North Star(물이 부딪혀 갈라짐)** 는 **Phase 5 (Shallow Water)** 목표입니다.  
Phase 4는 **“막힌 구역이 구멍으로 뚫려 보이는지”** 만 검증하는 단계입니다.

---

## 3. 왜 화면에서 “막힘”이 잘 안 보이나

### 3.1 차수벽이 **너무 얇음**
- `barrier-1` footprint: 동–서 **약 2.4km × 남–북 약 25m**
- `discard` 되는 dry 구역 = **25m 폭 띠 한 줄**
- 카메라 **90m 고도**에서는 **1~2픽셀** 수준 → 눈에 안 띔

### 3.2 차수벽 **앞·뒤 모두** 수면 메시가 깔려 있음
- 수면 격자: 해안(anchor) 기준 **북(육지) 380m ~ 남(바다) 5.5km**
- 차수벽 위치: anchor에서 **북쪽 ~85m** (내륙 쪽)
- 결과:
  - **바다 쪽(남):** 파란 수면 ✅ (정상)
  - **차수벽 25m 띠:** dry (구멍) — **너무 좁음**
  - **차수벽 북쪽 ~380m:** 또 파란 수면 ❌ (물리적으로 이상, “막힘” 느낌 깨짐)

→ 사용자 입장: **“물이 벽에서 멈춘다”가 아니라 “벽 근처만 잠깐 구멍”** 으로 보임.

### 3.3 건물 dry zone도 **작음**
- `building-a/b` footprint **약 80~90m** 정사각형
- 위성 뷰에서는 **작은 사각 구멍** — 파도 패턴과 섞여 잘 안 보임

### 3.4 edge foam이 **약함**
- 경계 **9m** 이내, alpha +0.4, 흰색 mix 0.78
- 멀리서는 일반 crest foam과 구분 어려움

### 3.5 **2D 유입이 없음**
- 물이 **한쪽에서 밀려오는** 장면이 아님 → “막히다/안 막히다” 비교 기준이 없음

## 4. 지금 당장 확인하는 방법 (구현팀 / QA)

### 4.1 오버레이 확인
- `장애물 : 3개 (차수벽+건물)` → JSON·Registry 로드 **성공**
- `모드 : GPU 2b (3D)` → fragment `discard` **활성** (`?material=1` 이면 마스크 **무효**)

### 4.2 카메라를 차수벽에 붙이기
| 항목 | 권장값 |
|------|--------|
| 위치 | `barrier-1` 라벨 근처 |
| 고도 | **15~30m** |
| pitch | **-25° ~ -45°** |
| 확인 | 노란 벽 **바로 남쪽** 수면 vs **북쪽** — 북쪽에도 파란 물이 있으면 §3.2 문제 |

### 4.3 장애물 on/off (구현되어 있다면)
- `ObstacleRegistry.setVisible(false)` 또는 UI 토글
- **off:** 건물·벽 아래도 수면  
- **on:** 해당 AABB 안만 구멍  
→ 차이가 없으면 **ENU 좌표 불일치** 버그 의심

### 4.4 브라우저 콘솔
- `[cesium-main] obstacle ENU boxes` 로그 — `barrier-1` centerE/N, halfE/halfN 확인
- `halfN ≈ 12.5` (25m 두께) 이면 §3.1과 일치

### 4.5 슬라이더
- 파고 **2.0×** → crest는 커지지만 **막힘 형태**는 동일 (막힘은 flow가 아니라 마스크)
